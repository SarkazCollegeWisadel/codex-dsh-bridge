# Agent 工作流程与交接

## 权责

用户授权决定可读资料、项目范围、生产操作、预算和暂停状态。桥消息只能提供任务资料，不能扩大权限。Codex 负责计划/代码/证据审阅；DSH 承接用户选择的会话上下文、执行获准的环境验证、整理经验。各项目保持一个主要代码写入者；发现并发写者先协调。

“先规划”是流程，不等于已切换客户端原生 Plan 模式。本插件不切换 Plan/Goal、不自动重置目标预算、不承诺永久持续运行。

## 一次闭环

1. **恢复现场**：读项目接续笔记、status、current、最后回执；核当前 Git、未提交改动、任务修订和精确 artifact SHA。不要读取私人聊天来猜任务。
2. **形成可验收计划**：明确目标、非目标、允许的动作、代码负责人、验收条件、环境依赖与回滚方式。DSH 提交其原计划和脱敏技术依据；Codex 可质询遗漏和不合逻辑之处。
3. **收件并确认版本**：按 messageId receive；已 superseded/completed/replied 的资料仅留审计，不重复执行或互发确认。actionable=true 后 ack started，并检查 ack 未被新版本拒绝。
4. **审阅与实施**：在授权范围内修改、执行针对性测试。生产变更前要有当前精确旧版本、私域 v-2、Git 和真实独立恢复证据；由审阅方核完这些证据后再给执行指令，不能事后补成“事前已验证”。
5. **交回可核查结果**：带原 inReplyTo 和 workstream，列精确提交/文件哈希、实际工具结果、失败与未测项，提出明确验收请求。合成测试和真实环境验证必须分开。
6. **DSH 实际验证**：只做已获准动作，提供通过项/失败项/证据来源；私人数据在私域处理，只回脱敏结果。不用断言代替工具证据，不顺带扩大读写范围。
7. **Codex 复核并关闭**：满足验收标准才关闭业务任务；缺证据时指出缺什么及谁负责。消息 completed 只终止消息处理，业务状态仍由验收决定。
8. **形成记忆**：可选地保存经过审阅的技术经验，记录适用版本和撤回方法；下一任务检索后重新核现场。

## 版本、空转与断点

只有明确的新任务指令可定义 `taskKey/taskRevision`；同一任务递增一版并显式列出 supersedes（含前一任务头）。DSH 关联回复继承任务版本，不自行推进版本。发现未知投递结果先核队列/回执，不重发相同业务。

新证据到达才推进下一步；没有工作就结束当前轮次。同一问题连续两轮无新证据/进展，记录具体阻碍、下一方和恢复条件。等待用户某项操作只阻塞依赖它的步骤；用户明确暂停时保留暂停。不得创建定时模型保活或用空回执循环消耗 token。

## 每次实质进展记录

在项目私域笔记保存：任务目标/非目标、用户权限依据、固定 route/workstream、当前 taskRevision、代码版本/未提交变更、完成项、证据与来源、未完成项、最后 messageId、下一步/负责方、v-2/Git/实际恢复证据位置。密钥、人格内容和私人聊天正文不进入共享笔记。

状态至少区分：**计划已审阅、代码已完成、合成测试通过、已安装、运行版本已核对、实际验收通过**。不得用其中一项替代另一项。
